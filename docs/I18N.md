# Project Nexus language and copy

Status: canonical policy. Revised 2026-10-27: **Project Nexus ships in English (en-US) only.** The product owner removed Simplified Chinese; there is no language selector and no language preference. This document owns user-facing terminology and copy mechanics; [DESIGN_SYSTEM](DESIGN_SYSTEM.md) owns layout and typography.

## 1. Message architecture

The frontend uses i18next with react-i18next and one bundled catalog: `src/locales/en-US/{common,navigation,home,agents,models,providers,extensions,system,settings,health,diagnostics,checks,findings,actions,errors,capability}.json`. Keeping copy in catalogs (rather than in components) keeps wording reviewable in one place and leaves a clean path if another language is ever authorized; adding one requires a new explicit product decision and a revision of this document.

Native/Rust code returns stable domain codes and safe typed parameters, not sentences. The frontend translates codes (`errors:<code>`, `checks:<id>.<detail>`, `findings:<code>.title`). The native menu and the native confirmation dialog read `src/locales/en-US/common.json` and `src/locales/en-US/native.json` at build time, so there is one source for each string.

Keys express meaning (`agents:liveReadyIssue`, `errors:config.concurrent_change`), never source sentences or positions. No ordinary user-facing strings in React components, CSS generated content, placeholders, tooltips, validation, accessibility attributes, toasts or menus; a unit test rejects JSX text and literal accessible labels. Product names, exact model IDs, paths, versions and user-entered labels are data and are shown verbatim. Use complete sentences with named interpolation; do not concatenate fragments. Do not render untrusted parameters as HTML.

## 2. Terminology authority

| Term | Rule |
| --- | --- |
| Project Nexus | Product name unchanged |
| AI Agent Lifecycle Manager | Product category |
| Agent / Agents | Navigation uses **Agents** |
| Models / Model | Primary navigation and general UI |
| Provider / Providers | Subordinate connection domain; never conflated with Model |
| Model Profile | Reusable named Provider + Model settings, revisioned |

| Extensions | Primary navigation, containing MCP and Skills |
| MCP | Explain “Model Context Protocol” on first educational use |
| Agent Health | Readiness assessment, never a numeric score |
| Diagnostics / Safe Repair | Structured explanation / reviewed, confirmed action flow |
| Ready / Needs attention / Blocked / Unknown / Unsupported | The five readiness states (see Architecture §6) |
| Unknown metadata | Distinct from the Unknown readiness state |
| Adopt | Keep the existing installation and configuration; never implies reinstall or ownership transfer |
| Verify / Verified | Evidence-based postcondition, not a process exit code |
| Restore configuration vs Undo this operation | New confirmed replacement from a backup vs compensation while preconditions still hold |
| Evidence | User-facing diagnostic detail |

Primary navigation order: Home, Agents, Models, Extensions, System, Settings. Agent Detail tabs: Overview, Model, Extensions, Configuration, Diagnostics.

## 3. Formatting

Use `Intl.DateTimeFormat` and `Intl.NumberFormat` with the `en-US` locale. Store UTC instants, render in the user's timezone, and show exact timestamps with timezone for evidence; relative “just now” must not hide stale evidence. Use i18next plural variants with a numeric `count` and complete phrases (“1 Agent needs attention” / “3 Agents need attention”). Sentence case throughout; avoid unexplained acronyms. Preserve model IDs and versions exactly. An unavailable price or metric is unknown, never zero.

## 4. Native error contract

Native errors carry `code`, typed `params` and `retryable`. Known codes map to `errors:<code>`; unknown codes fall back to a generic message plus the safe code. Parameters never contain secrets or raw upstream text. Upstream error output appears only as redacted, bounded evidence beneath a written summary, never as the main message.

## 5. Layout, accessibility and tests

Copy is part of design: content-driven widths, wrapping labels, long Provider names and 40% text-expansion fixtures. Critical consent text is never truncated; truncated technical values have a focusable full-value disclosure. Accessible names, descriptions, progress announcements and errors come from the catalog; row actions include the Agent name. The document language is `en-US`.

Automated checks: every catalog value non-empty and English-only, no hardcoded JSX strings or literal accessible labels, native menu and confirmation catalogs complete, and UI tests across themes, narrow desktop, reflow and reduced motion.
